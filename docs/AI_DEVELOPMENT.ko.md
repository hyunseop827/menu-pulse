# AI를 활용한 개발

[English](AI_DEVELOPMENT.md)

Menu Pulse는 Hyunseop Kim이 Claude Code를 비롯한 AI 코딩 도구를 활용해 만듭니다. 코드, 테스트, 스크립트, 문서는 AI가 작성하고 고칩니다. 무엇을 만들지는 메인테이너가 정하며, 결과를 검토하고 직접 써 본 뒤 언제 내보낼지 정합니다. 태그와 릴리스는 CI가 만듭니다.

## 역할

- **메인테이너**: 목표와 우선순위를 정하고, 제품 방향을 결정하며, 실제 Mac에서 빌드를 확인하고, 언제 내보낼지("올려") 정합니다.
- **AI 도구**: 변경을 구현하고, 테스트와 문서를 쓰고, 코드를 리뷰하며, [`AGENTS.md`](../AGENTS.md)에 따라 버전 번호와 릴리스 노트를 준비합니다. 메인테이너가 내보내라고 하면 커밋하고 풀 리퀘스트를 열어, CI를 통과하면 머지합니다. 태그와 배포는 CI가 하며, AI 도구가 직접 하지 않습니다.

## 변경을 검증하는 방법

- **컴파일러와 정적 분석**: 모든 경고를 오류로 처리하며, Clang 정적 분석에서 문제가 하나라도 나오면 `make check`가 실패합니다.
- **테스트**: `make check`가 테스트 실행 파일 4개, 빌드한 앱 번들 검사, 벤치마크 테스트를 실행합니다. CI도 풀 리퀘스트와 `main` 푸시마다 같은 검사를 돌린 뒤에야 릴리스를 배포합니다.
- **리뷰**: 여러 AI 리뷰어가 정확성, 안 쓰는 코드, 성능, 문서 같은 관점에서 따로 코드를 검토합니다. 다른 에이전트가 각 지적을 반박해 보고, 확인된 문제만 고칩니다.
- **실제 기기**: 테스트로 확인할 수 없는 동작은 Mac에서 직접 확인합니다. 예를 들어 온도는 센서 원본 값과, 디스크 수치는 Finder와 비교하고, 테스트용 사본으로 업데이트와 재시작을 확인하며, README 스크린샷은 현재 빌드로 찍습니다.

## 한계

- AI가 쓴 코드도 틀릴 수 있습니다. 리뷰와 테스트로 위험을 줄이지만 없애지는 못합니다.
- 온도 측정은 macOS 버전에 따라 바뀔 수 있는 비공개 IOKit 인터페이스를 사용합니다.
- 앱은 ad-hoc 서명을 사용하며 Apple 공증을 받지 않았습니다.

문제는 [GitHub Issues](https://github.com/hyunseop827/menu-pulse/issues)로 알려 주세요.

## 작업 기록

- **1.8.0**: 메인테이너의 요청으로 업데이트 방식을 앱 자체 업데이터에서 Sparkle 2로 바꿨습니다. 메인테이너의 다른 앱과 같은 방식으로, 하루 한 번 확인하고 사용자가 선택할 때만 설치하며, 개인 키를 메인테이너만 가진 EdDSA 서명으로 업데이트를 검증합니다.
